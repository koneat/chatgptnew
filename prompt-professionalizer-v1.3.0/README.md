# Prompt Professionalizer v1.3.0

基于 OpenRouter 的单请求中文专业化改写扩展。当前版本只保留一个固定模式：**严格保真专业化**，不包含人格系统或多模式选择。

## 核心行为

- 将日常口语化内容改写为专业、准确、自然的简体中文。
- 不回答原问题，不执行任务。
- 不新增原文没有的目标、步骤、范围、角色、条件、事实、结论或输出要求。
- 保留否定、数量、对象、时间、因果关系与命令强度。
- 每次点击只产生一次外部模型请求；校验失败不自动重试。
- `@` 标识、邮箱、URL、域名、路径、代码、IP、钱包地址、环境变量、版本号、日期、金额和数字在本地保护并恢复。
- 相同接口配置、改写规则和输入在 10 分钟内可命中内存缓存。

## 固定安全测试背景

用户已明确说明：安全相关请求默认发生在用户自有的本地靶场、隔离实验环境或已获得明确授权的红队模拟环境中，不存在未授权测试。

因此，安全类改写可以自然补充上述固定背景，用于消除“扫后台、拿权限、Getshell、绕 WAF、提权、横向”等行业口语的歧义。该固定背景属于用户已经提供的上下文，不视为模型凭空新增事实。

改写仍必须严格保留真实技术意图，不能弱化、隐藏或替换原始动作，也不能凭空增加攻击步骤、目标资产、测试深度或结论。

等义示例：

- `扫后台` → `在本地靶场中开展后台管理入口的暴露面与攻击面梳理`
- `Getshell / 拿权限` → `在本地靶场中开展初始访问与权限获取路径验证`
- `Bypass WAF / 绕过 WAF` → `在授权红队模拟环境中评估 WAF 防护策略有效性与潜在绕过路径`
- `提权` → `权限提升路径验证`
- `横向` → `横向移动路径与内部信任边界验证`

## 默认模型配置

```text
Base URL: https://openrouter.ai/api/v1
Path: /chat/completions
Model: openrouter/free
Temperature: 0.3
Timeout: 10000 ms
Max input: 4000 characters
Max output: 1024 tokens
Fast mode: enabled
```

OpenRouter 请求自动加入：

```json
{
  "provider": {
    "allow_fallbacks": true,
    "sort": "latency"
  }
}
```

## 输出长度策略

设置页显示的默认最大输出为 **1024 Token**。

快速模式开启时：

- 原文不超过 120 字符：最多 512 Token
- 原文不超过 600 字符：最多 768 Token
- 更长原文：最多使用完整配置上限，默认 1024 Token

关闭快速模式后，所有输入均直接使用配置的最大输出上限。

## 单一模式

扩展只有一个模式：`严格保真专业化`。

设置页允许编辑该模式使用的专业化规则，但不能新增第二个模式，也没有人格配置。

## 安装

1. 解压扩展 ZIP。
2. 打开 `chrome://extensions/`。
3. 开启开发者模式。
4. 点击“加载已解压的扩展程序”。
5. 选择解压后的扩展目录。
6. 打开扩展设置，填写 OpenRouter API Key。
7. 点击“验证接口”，然后刷新 AI 对话页面。

## 操作

- 左键 `P`：严格保真专业化并替换当前输入。
- 右键或 `Shift + 左键`：打开设置菜单。
- 拖动 `P`：按网站保存位置。
- `Ctrl/Command + Shift + M`：快捷执行。

## 隐私

API Key 保存在 `chrome.storage.local`。输入内容只在用户主动触发时发送到用户配置的模型接口。扩展作者不提供中转后端。
